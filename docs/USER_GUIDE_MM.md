# 9Floor Fc Espresso Menu V2 — အသုံးပြုနည်း

ဤလမ်းညွှန်သည် တည်ဆောက်ထားသော V2 UI အတွက် ဖြစ်သည်။ Online Admin၊ Publish၊ ပုံတင်ခြင်းတို့သည် Supabase/Vercel ချိတ်ဆက်ပြီး စမ်းသပ်အောင်မြင်မှ အသုံးပြုနိုင်မည်။

## မီနူးကြည့်ရန်

1. ပင်မစာမျက်နှာတွင် Barista ကော်ဖီလိုင်း သို့မဟုတ် အအေးစုံလိုင်းကို ရွေးပါ။ ကော်ဖီအအေးများသည် Barista ဘက်တွင် ရှိသည်။
2. Search တွင် English မီနူးနာမည်၊ ပါရှိသော မြန်မာနာမည်၊ မီနူးနံပါတ် သို့မဟုတ် recipe ID ရိုက်ပါ။ 21-02 ကဲ့သို့ ရှာနိုင်သည်။
3. အမျိုးအစား selector ဖြင့် စစ်ထုတ်နိုင်သည်။ မီနူးမတွေ့လျှင် search ဖျက်ပြီး အမျိုးအစား အားလုံး ပြန်ရွေးပါ။
4. မီနူး card ကို နှိပ်လျှင် သက်ဆိုင်ရာ ပါဝင်ပစ္စည်းနှင့် ဖျော်နည်းစာမျက်နှာ ဖွင့်သည်။
5. နှလုံးခလုတ်နှိပ်၍ အကြိုက်ဆုံးသိမ်းနိုင်သည်။ ဤဖုန်း/ဤ browser တွင်သာ သိမ်းသည်။ Account အကြား sync မပါ။
6. အောက်ဘက် navigation မှ နိုင်ငံတကာစတိုင်၊ အကြိုက်ဆုံး၊ ကြည့်ပြီးစာရင်းသို့ ဝင်နိုင်သည်။ Desktop တွင် အပေါ် navigation နှင့် စာမျက်နှာခလုတ်များ သုံးပါ။
7. လ/နေ ခလုတ်က အမှောင်/အလင်း အပြင်အဆင် ပြောင်းသည်။

## နိုင်ငံတကာစတိုင်များ

ဗီယက်နမ်၊ အီတလီ၊ ထိုင်း၊ ကိုရီးယား၊ အင်ဒိုနီးရှား၊ ဂရိ၊ တူရကီ၊ စပိန်၊ ပြင်သစ်၊ မက္ကဆီကို၊ ကျူးဘား၊ အမေရိကန် ခေါင်းစဉ်များ ပါသည်။ မူရင်းမီနူးများကို ပြန်ညွှန်းသော ခေါင်းစဉ်များ ဖြစ်၍ မီနူးထပ်မပွားပါ။ မူရင်းစမ်းသပ်ဖျော်နည်းအဆင့်ကို ဆက်ထိန်းထားသည်။

## ဖျော်နည်းအတိုင်း လိုက်လုပ်ရန်

ပစ္စည်းနှင့် ပမာဏကို အရင်ဖတ်ပါ။ မူရင်းပါ ခွက်အရွယ်ကိုသာ အသုံးပြုပါ။ ရရှိထားသောဒေတာမရှိဘဲ 8/12/16/22 oz အားလုံးကို ခန့်မှန်းမထည့်ထားပါ။

ခွက်အရေအတွက် 2၊ 3 စသည် ရွေးလျှင် ပါဝင်ပစ္စည်း စုစုပေါင်းပမာဏ တိုးပြသည်။ ဥပမာ 150–180 g ကို နှစ်ခွက်အတွက် 300–360 g ပြသည်။ အောက်ဖျော်နည်းအဆင့်များသည် တစ်ခွက်စာ မူရင်းပမာဏအတိုင်း ဖြစ်၍ ခွက်တစ်ခွက်ချင်း ဖျော်ပါ။ မသေချာသော ပမာဏကို × အရေအတွက်ဖြင့် ပြပြီး မူရင်းစာသား မပြောင်းထားပါ။

အဆင့်ပြီးတိုင်း checkbox ကို တို့နိုင်သည်။ “အဆင့်များ ပြန်စရန်” နှိပ်၍ reset လုပ်နိုင်သည်။

ကြက်ဥပါမီနူးများတွင် pasteurized ကြက်ဥ/အနှစ်ကိုသာ အသုံးပြုရန် safety notice ပါသည်။ ရိုးရိုးကြက်ဥအစိမ်းကို ကော်ဖီပူလောင်းရုံဖြင့် စိတ်ချရသည်ဟု မယူဆပါနှင့်။ FDA လမ်းညွှန်: https://www.fda.gov/food/buy-store-serve-safe-food/what-you-need-know-about-egg-safety

## Home Screen တွင် ထည့်ရန်

- iPhone: Safari တွင် အမှန်တကယ် deployed URL ကို ဖွင့်ပါ။ Share → Add to Home Screen → Add ကို ရွေးပါ။
- Android: Chrome တွင် deployed URL ကို ဖွင့်ပါ။ menu → Install app / Add to Home Screen ကို ရွေးပါ။ ပံ့ပိုးသော browser တွင် app အောက်ခြေ install ခလုတ် သုံးနိုင်သည်။

အသစ်တင်တိုင်း မပြောင်းသော app URL ကိုသာ Home Screen တွင် သိမ်းပါ။ Preview တစ်ကြိမ်ချင်းစီ၏ URL မတူသော link ကို မသိမ်းပါနှင့်။

ZIP ကို Files preview မှ ဖွင့်ခြင်းသည် HTTPS ဖြင့် host လုပ်ထားသော PWA နှင့် မတူပါ။

## Update ရရှိပုံ

မီနူး publish ပြီးပါက internet ရသော ဖုန်းတွင် app ကို ပြန်ဖွင့်ပါ။ foreground ပြန်ရောက်ချိန်နှင့် ဖွင့်ထားစဉ် တစ်မိနစ်တစ်ခါ update စစ်သည်။ Connection ပြတ်နေချိန်တွင် သိမ်းထားသော မီနူးကိုသာ ပြသည်။ Internet ပြန်ရမှ အသစ်ယူနိုင်သည်။

App code version အသစ်ကို အမှန်တကယ် deploy ပြီး SW အသစ် အဆင်သင့်ဖြစ်ပါက “ဗားရှင်းအသစ် ရရှိပါပြီ” ပေါ်သည်။ “ယခု Update လုပ်မည်” ကို နှိပ်ပါ။ ပြန် install မလိုရန် စီစဉ်ထားသည်။ ChatGPT ထဲ code ပြင်ရုံဖြင့် live app မပြောင်းပါ။

အော့ဖ်လိုင်းသုံးရန် internet ရစဉ် app ကို ဖွင့်၍ “နောက်ဆုံးမီနူးများ သိမ်းပြီးပါပြီ” ပြသည်အထိ စောင့်ပါ။ ဓာတ်ပုံသည် ကြည့်ဖူးပြီး cache ရှိမှ offline ရနိုင်သည်။ ဖုန်းက website storage ကို ဖျက်လိုက်ပါက offline မီနူးများ ပြန် download လုပ်ရမည်။

## Admin မီနူးထည့်/ပြင်ရန်

1. အောက်ခြေ “စီမံခန့်ခွဲသူ ဝင်ရန်” ကို နှိပ်ပါ။ ခွင့်ပြုထားသော Admin email/password ဖြင့် ဝင်ပါ။
2. မီနူးတစ်ခုရွေး သို့မဟုတ် “မီနူးအသစ်” နှိပ်ပါ။
3. အမည်၊ နံပါတ်၊ အမျိုးအစား၊ Barista/အအေးလိုင်း၊ ခွက်အရွယ်နှင့် ပမာဏများ ထည့်ပါ။ မူရင်းစမ်းသပ်မီနူးကို လက်တွေ့စမ်းပြီးမှ ပိုင်ရှင်အတည်ပြုအဆင့်သို့ ပြောင်းပါ။
4. ဖျော်နည်းအဆင့်တစ်ခုစီကို စာကြောင်းသီးသန့် ရေးပါ။
5. လိုအပ်ပါက “Draft သိမ်းမည်” ကို နှိပ်ပါ။ Draft သိမ်းရုံဖြင့် ဖုန်းများတွင် မပြောင်းသေးပါ။
6. Preview တွင် မီနူးအရေအတွက်နှင့် လက်ရှိရွေးထားသော မီနူးကို စစ်ပါ။ “အတည်ပြုပြီး ထုတ်ပြန်မည်” နှိပ်မှ အက်ပ်ဒေတာ ပြောင်းမည်။
7. အခြား Admin က အရင်ထုတ်ပြန်ထားလျှင် version conflict ပြမည်။ မိမိ Draft ကို JSON ထုတ်သိမ်းပြီး နောက်ဆုံးဒေတာဖြင့် ပြန်ညှိပါ။ တိတ်တဆိတ် အစားမထိုးပါ။

Draft တစ်ခုကို Admin များပူးတွဲသုံးသည်။ တစ်ချိန်တည်းတစ်ဦးသာ ပြင်ဆင်ရန် အကြံပြုသည်။ နောက်ဆုံးထုတ်ပြန်ထားသော release ကိုသာ concurrent-version protection က ကာကွယ်သည်။ Draft အဆင့်မှာ နောက်ဆုံးသိမ်းသူ၏ data ဖြစ်မည်။

## ပုံတင်ရန်

မိမိရိုက်ထားသော သို့မဟုတ် အသုံးပြုခွင့်ရှိသော သက်ဆိုင်ရာ သောက်စရာဓာတ်ပုံအစစ်ကို ရွေးပါ။ JPEG/PNG/WebP 4 MB အောက် သုံးပါ။ HEIC ကို JPG သို့ အရင်ပြောင်းပါ။ ပုံတင်ပြီး Preview စစ်ကာ Publish လုပ်ပါ။ မီနူးမသက်ဆိုင်သော stock photo ကို မတင်ပါနှင့်။

## ဖျက်ရန်၊ Backup နှင့် Restore

မီနူးဖျက်ရာတွင် confirmation ပါသည်။ Draft မှ ဖျက်ပြီး Publish လုပ်မှ public menu မှ ပျောက်မည်။

“JSON ထုတ်မည်” က လက်ရှိ Draft တစ်ခုလုံးကို backup ထုတ်သည်။ ပုံ URL ပါပြီး ပုံဖိုင် bytes မပါ။ “JSON သွင်းမည်” က format/duplicate/category စစ်ပြီး Draft အဖြစ်သာ အစားထိုးသည်။ စစ်ဆေးပြီးမှ Publish လုပ်ပါ။ မသိမ်းရသေးသောအလုပ် အစားထိုးမီ backup ထုတ်ထားပါ။

“ဗားရှင်းမှတ်တမ်း” မှ မူဟောင်းကို ရွေးလျှင် Draft အဖြစ် ပြန်ယူသည်။ ထပ် Publish လုပ်လျှင် revision အသစ်နံပါတ် ရရှိ၍ ဖုန်းတွင် rollback data ကို အသစ်အဖြစ် ရယူနိုင်သည်။

JSON backup သည် ပုံဖိုင်နှင့် database infrastructure backup ကို အစားမထိုးနိုင်ပါ။ Storage ပုံများကို သီးသန့် backup လုပ်ပြီး version retention ကို စောင့်ကြည့်ပါ။

## GitHub Pages မိတ္တူ

GitHub Pages reader တွင် မီနူးကြည့်ခြင်း၊ search၊ favorites၊ recent၊ offline နှင့် update အသိပေးမှု ပါသည်။ Server-backed Admin ကို မပြထားပါ။ ထုတ်ပြန်ရန်အတွက် approved source change နှင့် GitHub Pages deployment အောင်မြင်ရန် လိုသည်။ Full Admin မိတ္တူကို Supabase/server hosting ချိတ်ဆက်ပြီးမှ သီးခြားအသုံးပြုနိုင်မည်။
